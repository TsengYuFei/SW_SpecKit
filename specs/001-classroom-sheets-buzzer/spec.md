# Feature Specification: 課堂搶答與 Google Sheets Guided Notes

**Feature Directory**: `specs/001-classroom-sheets-buzzer`

**Created**: 2026-11-24

**Status**: Implemented and validated

**Input**: 將學生上台寫答案的課堂搶答改為本機運行的分組線上活動，直接讀取老師的線上 Guided Notes，並將各題成功答案回寫至原試算表。

## Clarifications

### Session 2026-11-25

- Q: 本階段是否必須測試不同實體裝置跨網路連入？ → A: 先不測跨裝置；在同一台電腦的不同瀏覽器中，取得活動網址即可匿名加入，作為目前驗收範圍。
- Q: 重啟驗收是否必須重新啟動整台電腦？ → A: 改測實際停止並重新啟動 Node.js 服務，確認記憶體活動清空及舊活動失效。

### Session 2026-11-24

- Q: 系統應根據什麼線索辨識線上 Guided Notes 的題目和對應填空格？ → A: 依提供的既有教材版型辨識單題和題組。題組所有小題須完整作答並一次送出。

- Q: 學生應如何加入自己的組別並取得作答權限？ → A: 老師建立活動時設定組別數；學生免登入點選空組，每組限一個匿名瀏覽器身分，加入後可為組別命名。

- Q: 如果學生換裝置或清除瀏覽器資料，應如何取回原組的作答權限？ → A: 組別綁定持續至活動結束，只有原匿名瀏覽器身分可回到該組。

- Q: 如果老師的電腦在活動進行中重啟，重新開啟系統後應該如何處理這場活動？ → A: 老師重新建立活動，學生重新選組並作答。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師連線並確認題目 (Priority: P1)

老師以 Google Sheets URL 或 Spreadsheet ID 開啟自己的線上 Guided Notes，完成 Google 授權後，確認系統辨識出的題目與填空位置。

**Why this priority**: 老師能沿用既有教材並確認答案將寫入正確位置。

**Independent Test**: 使用兩份題數、分頁名稱和儲存格位置不同的真實線上測試試算表，分別以 URL 和 ID 連線，比對題目與填空位置。

**Acceptance Scenarios**:

1. **Given** 老師具備試算表讀寫權限，**When** 以 URL 或 ID 完成授權並讀取，**Then** 顯示所有題號、題目及對應填空位置，涵蓋有題目的各分頁，並列出各題組所含的小題及個別填空位置。
2. **Given** 題目與填空對應有歧義或未找到題目，**When** 老師讀取教材，**Then** 系統說明問題，並要求修正來源後重新讀取才可開始。
3. **Given** 輸入無效、試算表不存在、授權取消或權限不足，**When** 老師嘗試連線，**Then** 顯示對應錯誤並提供修正或重試方式。

### User Story 2 - 老師控制活動，學生分組搶答 (Priority: P1)

老師建立活動時設定可參與的組別數，並控制活動開始與結束。學生免登入，點選空組加入後可設定組名，例如「第一組－咕咕嘎嘎」，並代表該組提交答案。老師在活動中查看各組進度與暫定結果。

**Why this priority**: 全班需要共用活動階段與收件順序，學生需要公平且私密的作答環境。

**Independent Test**: 以一位老師和至少兩組學生操作已載入題目的活動，比對不同階段下的權限、收件順序與畫面。

**Acceptance Scenarios**:

1. **Given** 老師確認題目且兩組學生已加入，**When** 老師開始或結束活動，**Then** 已連線的學生端同步顯示新階段，系統只在活動進行中接受答案。
2. **Given** 兩組學生在活動中提交同一題，**When** 系統接受答案，**Then** 依共同收件順序選出唯一成功組，老師可立即查看各組狀況及暫定結果。
3. **Given** 活動尚未結束，**When** 學生查看活動或嘗試取得其他組資料，**Then** 只可查看自己組別的提交狀態，無法取得其他組的答案、進度或順位。
4. **Given** 學生嘗試代替其他組作答或操作教師功能，**When** 系統收到請求，**Then** 拒絕操作且活動資料維持一致。
5. **Given** 同一組已成功提交某題，**When** 同組重送或另送一份答案，**Then** 保留第一次有效提交及原收件順序。

6. **Given** 題組有多個小題，**When** 學生只送出部分答案，**Then** 系統拒絕整筆提交並指出未作答的小題，且不記入順位。補齊後可一次送出全部答案。

7. **Given** 老師建立活動時設定兩組，**When** 學生開啟活動頁並點選空組，**Then** 可免登入加入該組並設定組名，組別編號仍可辨識。
8. **Given** 兩個不同瀏覽器身分同時選同一空組，**When** 系統處理加入，**Then** 只有一個成功；另一方看到組別已被占用。已加入的身分重新連線可回到原組。

9. **Given** 學生已加入某組且活動尚未結束，**When** 學生換裝置或清除用於識別的瀏覽器資料後嘗試回到原組，**Then** 原組維持占用，該次加入遭拒，既有組名、答案及順位維持原樣。

10. **Given** 活動進行中已有學生選組並提交答案，**When** 老師的電腦重啟後重新開啟系統，**Then** 系統告知原活動已中斷，老師可建立新活動，學生須重新選組並作答，新活動的組別及結果從空白開始。

### User Story 3 - 公布結果並直接回寫 (Priority: P1)

活動結束後，老師與學生查看逐題結果。老師確認結果後，將成功答案回寫原線上試算表。

**Why this priority**: 班級能確認各題結果，老師能在原教材保留答案。

**Independent Test**: 以包含有答案和無答案題目的已結束活動驗證雙方結果，再由老師回寫並直接查看原試算表。

**Acceptance Scenarios**:

1. **Given** 活動已結束，**When** 老師與學生查看結果，**Then** 兩方都看到各題題號、成功組及其答案，未作答題顯示無成功組。題組共用一個成功組，並逐一顯示該組的小題答案。
2. **Given** 目標位置與已確認的對應一致且老師具有寫入權限，**When** 老師執行回寫，**Then** 只有原試算表中有成功答案的對應填空格更新，題組的各小題答案依原對應位置分別填入，系統在確認寫入後才顯示成功。
3. **Given** 目標位置或內容有衝突、權限被撤銷、網路中斷或 Google 服務回報錯誤，**When** 老師執行回寫，**Then** 系統說明問題，保留活動結果，並顯示已確認或尚未確認的寫入狀態。

### Edge Cases

- 同時收到多組答案時，依共同活動記錄的收件先後唯一排序。接收時間相同時，以該記錄的先後次序決定。學生裝置的時間不影響順位。
- 提交與結束幾乎同時發生時，以共同活動記錄的先後為準。結束後收到的答案拒絕；斷線重送也須依當前階段判定。
- 空白答案、未知題目、未有效加入的組別及無效階段操作皆須拒絕。拒絕的操作不改動既有答案或順位。
- 學生以同一瀏覽器身分重新連線時，須回到原組並取得目前階段及允許查看的資訊。重新整理或暫時斷線不會解除綁定。換裝置或清除用於識別的瀏覽器資料後，若無法辨識為原瀏覽器身分，原組在本場活動結束前維持占用。
- 老師電腦重啟中斷進行中的活動時，學生端須顯示連線中斷或活動已不可用。學生已連線至仍在執行的同一活動時，短暫斷線後仍適用原組別綁定規則。
- 回寫逾時且無法確定是否寫入時，先顯示待確認。重試前須核對原試算表，避免重複寫入或覆蓋後續編輯。
- 授權失敗、外部服務錯誤或連線中斷時，錯誤畫面及紀錄須排除憑證和權杖。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統須可在老師的本機運行，老師及同一台電腦上不同瀏覽器的學生端使用同一場活動。學生透過活動網址匿名加入，不需登入；本次不要求跨裝置 LAN 驗收。
- **FR-002**: 系統須辨識老師與學生角色，並在每項操作檢查權限。只有老師可連線教材、確認題目、控制階段、查看全組進度及回寫。學生只能代表所屬組別提交答案。
- **FR-003**: 老師須可輸入 Google Sheets URL 或 Spreadsheet ID，完成 Google 授權後直接連線其線上 Guided Notes。讀取與回寫全程禁止要求或使用 `.xlsx`、`.csv` 或其他中介檔案。
- **FR-004**: 系統須動態辨識所有題目及其填空位置，支援不同題數、分頁名稱與儲存格位置。依教材中的「題號」「題目」「作答」表頭辨識對應區域。題號格跨列合併時，依其涵蓋範圍與作答區的小題編號（如「（1）」）辨識各小題，並以同列對應的空白格為其填空位置。單列單題的作答區若為合併格，以合併範圍的左上儲存格為填空位置。活動開始前須顯示單題、題組、小題與填空位置供老師確認。無題目或對應不明時須指出問題並阻止開始。
- **FR-005**: 老師須可將活動依序從待開始切換為進行中及已結束。系統須即時同步階段至所有已連線學生端，並在重新連線時顯示目前階段。
- **FR-006**: 系統只在活動進行中接受學生所屬組別對有效題目的非空白答案。每組每個單題或題組以第一次有效提交為準。題組須一次提交所有小題的非空白答案，缺漏或單獨送出任一小題時須拒絕整筆提交。無效、重複或逾時提交須提供可理解的狀態且不得改動順位。
- **FR-007**: 系統須依共同活動接收有效答案的時間及收件先後，確定每個單題或題組唯一的搶答成功組，取最早有效提交的組別及答案。題組以完整提交的共同收件順序判定，所有小題共用同一成功組。
- **FR-008**: 活動期間老師須可即時查看各組作答狀況及各題暫定結果。活動結束前學生無權取得其他組別的答案、作答進度或搶答順位。
- **FR-009**: 活動結束後，老師與學生均須可查看各題題號、成功組別及其答案。題組須顯示共用的成功組及各小題答案。無有效提交的單題或題組須顯示無成功組。
- **FR-010**: 活動結束後，系統須允許老師直接把成功答案寫回原線上試算表的對應填空格，題組各小題的成功答案須分別寫入各自的原填空格，並保留其他儲存格及未作答題目的內容。回寫前須重新核對來源，對應失效或內容已變更時須指出衝突並停止寫入該題或題組。老師須在預檢開始至寫後確認完成期間暫停其他人直接編輯來源，系統須顯示此操作前提；Google Sheets 預檢與寫入間的外部競爭修改無法由系統保證攔截。
- **FR-011**: 系統須以易理解的訊息說明網址或 ID 無效、找不到試算表、授權或權限不足、網路中斷與 Google 服務錯誤。外部服務能確定原因時須顯示對應原因；無法區分不存在或無權存取時，須明列兩種可能及檢查方式。外部服務未確認讀取或寫入完成時，須顯示失敗或待確認，並保留可安全重試所需的活動結果。
- **FR-012**: Google 憑證、金鑰及存取權杖禁止寫入程式碼、文件、日誌、Git 歷史或 AI 對話紀錄。錯誤訊息、測試資料及診斷紀錄均須排除真實機密值。

- **FR-013**: 老師建立活動時須設定可參與的組別數，系統須依設定建立對應數量的可選組別。學生開啟活動頁後可免登入點選空組。每場活動中，同一匿名瀏覽器身分只能加入一組，每組只能由一個匿名瀏覽器身分加入。成功加入後，該身分可設定該組名稱，組別編號須保留。組別綁定持續到活動結束。只有原瀏覽器身分可重新進入該組；活動中學生及老師均不能解除或轉移綁定。

- **FR-014**: 老師本機的 Node.js 服務重新啟動（含電腦重啟造成的服務重啟）中斷進行中的活動後，系統須說明須重新建立活動。新活動須重新選組並作答，前一場的組別綁定、組名、提交與順位不得帶入新活動。中斷的活動不得當成老師已結束的活動公布或回寫。

### Key Entities *(include if feature involves data)*

- **活動**：由老師管理，包含目前階段、來源教材、參與組別與逐題結果。
- **Guided Notes**：原線上試算表，包含分頁、題目及供回寫的填空位置。
- **題目**：為單題或題組，包含活動中可辨識的題號。單題含一個作答項目，題組含多個小題。每個作答項目各有題目內容及來源填空位置。
- **組別**：在同一活動中可識別的學生作答單位，包含固定組別編號、選填組名及至多一個已加入的匿名瀏覽器身分。
- **提交**：包含單題或題組、組別、各作答項目的答案、共同接收時間與收件次序。
- **搶答結果**：逐題記錄成功組及其答案，或標示無成功組。
- **回寫結果**：記錄目標填空位置的寫入確認、衝突或待確認狀態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一位老師和至少兩組學生完成一次真實線上教材的端到端驗收，涵蓋授權、讀取、開始、作答、結束、雙方查閱及原教材回寫。全程使用的中介檔案數為零。
- **SC-002**: 兩份驗收教材使用不同題數、分頁名稱及填空配置。兩份教材合計須包含單題及至少一個多小題題組。所有單題、題組、小題與填空位置均須與人工核對結果完全相符。
- **SC-003**: 在本機服務與同機不同瀏覽器的學生端連線正常時，至少兩組學生的開始與結束畫面，以及老師看到的有效提交狀況，均在對應事件發生後 2 秒內更新。
- **SC-004**: 針對先後提交、同時提交、重複提交及接近結束時提交的驗收案例，每個單題或題組的成功組及答案均與共同活動已接受的第一筆有效提交相符。單獨提交小題或漏答的題組提交，計入順位的筆數為零，且結束前學生端可取得的其他組作答資料為零。
- **SC-005**: 成功回寫後，原教材中有成功答案的填空格內容均與公布結果相符，非目標儲存格的變更數為零。各指定連線及回寫失敗案例均顯示對應且可理解的狀態，誤報完成次數為零。

- **SC-006**: 老師設定兩組後，學生頁顯示兩個可選組別。兩個不同瀏覽器身分同時選同一空組時，成功加入的身分數恰為一；成功者可設定組名，失敗者可選另一空組。原身分可重新連線回到原組；在活動結束前，以新身分接管該組的成功次數為零。

- **SC-007**: 驗收時，在至少一組已有有效提交後，實際停止並重新啟動老師本機的 Node.js 服務。老師重建活動後，沿用的組別綁定、組名、提交及順位各為零，學生可重新選組並提交新答案。

## Assumptions

- 老師的本機可連線至網際網路，學生以同機的不同瀏覽器開啟活動網址。老師具有來源試算表的讀取權限，執行回寫時須另有對應儲存格的編輯權限。
- 回寫驗收須在來源暫停其他人編輯的條件下進行，來源變更的衝突案例在回寫預檢前安排。
- Guided Notes 的題號、題目與空格關係須能依既有教材版型辨識。提供的 Excel 附件是規格參考，功能驗收素材須置於線上 Google Sheets。驗收使用能判定對應關係的教材，另以有歧義的教材驗證錯誤情境。
- 每場活動使用一份來源試算表，可跨分頁讀題。每題最早有效提交即為成功，本次範圍以提交順序判定，不包含答案正誤評分。
- 每組由一個匿名瀏覽器身分代表，每個單題或題組接受該組一次有效提交。2 秒為連線正常時的驗收預設值。
- 本規格描述預定行為。依憲章，規劃階段須先以 PlantUML 呈現角色互動、階段轉換、同時或重複提交及逾時情境，並完成審查後再實作。
